# การแก้ผลตรวจคลาดเคลื่อนจากคลิปวันที่ 21 ตุลาคม 2026

พบสองปัญหาหลัก: วงรอบส่งภาพ SOP รอผลอ่าน QR ทำให้ในงานที่พบปัญหาได้รับเพียง 24 ภาพใน 88.6 วินาที และ backend ล็อกสถานะ `uncertain` ทุกกรณีเป็นการผิดลำดับ แม้เกิดจากภาพถูกบังหรือยังไม่นิ่ง

การแก้ไข:

- อ่าน QR และส่งภาพ SOP ด้วยวงรอบแยกกัน โดยแต่ละวงรอบมีคำขอค้างได้หนึ่งรายการ ใช้ canvas แยก และทิ้งผล QR ที่กลับมาหลังเปลี่ยนงานหรือปิดกล้อง
- ประมวลผลภาพ SOP และเขียนหลักฐานใน thread pool เพื่อให้ไม่ขวางการรับส่งคำขออื่น
- ใช้ธงผิดลำดับและธงลำดับกำกวมโดยตรงในการล็อกงาน สถานะไม่แน่ใจจากภาพบังกลับมาตรวจความนิ่งใหม่ได้
- ใช้หลักฐานขั้นตอนที่เคยยืนยันแล้วตรวจลำดับ โดยตรวจการมองเห็นและความนิ่งปัจจุบันแยกกันก่อนจบงาน ประวัติแต่ละขั้นไม่ถูกเพิ่มซ้ำหลังภาพกลับมา
- งานที่ขาดชิ้นส่วน ถูกบังตอนจบ ลำดับย้อน หรือลำดับยังไม่ชัดเจนยังผ่านไม่ได้ และไม่แก้ผลเก่าให้ผ่านย้อนหลัง

เพิ่มวิดีโอกล้องจริงเป็น regression fixture และทดสอบผ่าน API เดียวกับมือถือ มีการทดสอบเบราว์เซอร์ให้ QR อ่านช้า 2.5 วินาที ขณะที่เฟรมตรวจ SOP ยังส่งต่อได้

## โหมดตรวจเร็วตามคำขอล่าสุด

งานใหม่ทุกสเตชั่นและหน้าตรวจสด/อัปโหลดใช้ `require_stability=false` เป็นค่าเริ่มต้น เห็นสี ตำแหน่ง ขนาด และความสัมพันธ์กับฐานตรงเกณฑ์สองเฟรมติดต่อกันก็ยืนยันได้ ไม่รอเวลา dwell ความนิ่งของกรอบ หรือหยุดการเคลื่อนไหว

ยังต้องยืนยันขั้นก่อนหน้าก่อนขั้นถัดไป ลำดับกำกวมหรือย้อนยังถูกล็อก ภาพสุดท้ายต้องเห็นชิ้นส่วนครบ และต้องได้รับวิดีโอก่อนส่งต่อ ค่า `stable_seconds` ใช้เฉพาะการตั้ง `require_stability=true` ซึ่งยังคงมีชุดทดสอบเดิมแยกไว้
