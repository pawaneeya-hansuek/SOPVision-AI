# SOPVision AI · Hybrid Assembly Inspection

## ตำแหน่งไฟล์ในโปรเจกต์

- เปิดระบบ: `start_windows.bat` และ `start_mobile.bat`
- โค้ดระบบ: `main.py` และไฟล์ Python ประกอบที่ตำแหน่งเดิม
- หน้าเว็บ: `static/` · ชุดทดสอบ: `tests/`
- คู่มือ: [docs/PROJECT_LAYOUT.md](docs/PROJECT_LAYOUT.md)
- ภาพตัวอย่าง: `output/previews/` · QR / เอกสารที่สร้าง: `output/`
- ผลทดสอบและแคช: `artifacts/` · สำรองข้อมูลเก่า: `backups/legacy/`

ใน VS Code ไฟล์ประกอบจะแสดงเป็นกลุ่มใต้ `main.py`, `README.md` และ `start_windows.bat` กดลูกศรเพื่อขยายกลุ่มได้ ส่วนไฟล์ชั่วคราวและไลบรารีจะถูกซ่อนจาก Explorer โดยยังอยู่ในเครื่องครบ

ต้นแบบเว็บแอปตรวจลำดับการประกอบชิ้นงานผ่าน **Live Webcam**, **Video Upload** และ **QR Production Flow** ที่สแกนใบงานเพื่อเริ่มกล้องบันทึกวิดีโอ ตรวจ SOP แยกสถานี และล็อกการส่งต่อไปสถานีถัดไปจนกว่าจะตรวจผ่าน เก็บรายงาน/เวลาที่พบชิ้นส่วน/ภาพหลักฐาน และรองรับ **Gemini AI Review (เสริม)**

> **ความจริงทางเทคนิค:** ระบบตรวจสีและนับชิ้นส่วนที่เห็นในภาพ ยืนยันตามลำดับที่กำหนดด้วยภาพต่อเนื่อง 2 เฟรม ไม่ตรวจตำแหน่งติดตั้งหรือคุณภาพการประกอบจริง และไม่ใช่โมเดล AI ตรวจชิ้นงาน ส่วน Gemini เป็น *second opinion* แบบเลือกใช้ ไม่เปลี่ยนผลตรวจหลัก

## ตรวจสีและจำนวนชิ้น

- กำหนด SOP ด้วยลำดับ ชื่อ และสีของแต่ละขั้นตอน ระบบนับจำนวนชิ้นแยกตามสีจากภาพทั้งหมด ไม่ต้องตั้งกรอบกล้องหรือปรับตำแหน่ง
- ยืนยันสีและจำนวนด้วย 2 เฟรมต่อขั้นตอน; ถ้าข้ามลำดับหรือจำนวนไม่ครบ/เกิน งานจะไม่ผ่าน
- ตรวจสดส่งภาพทุก 80 ms; ก่อนผ่านงานตรวจภาพล่าสุดซ้ำอีกครั้ง วิดีโอย้อนหลังเป็นข้อมูลเสริม
- สแกน QR ด้วยกล้องผ่าน BarcodeDetector เมื่อเบราว์เซอร์รองรับ หรือใช้เครื่องอ่าน QR แบบ USB/กรอกรหัสงาน

## เปิดบน Windows (แนะนำ)

1. ติดตั้ง Python 3.11+ จาก python.org และเลือก Add Python to PATH
2. แตก ZIP แล้วดับเบิลคลิก **`start_windows.bat`** (ครั้งแรกต้องมีอินเทอร์เน็ตเพื่อติดตั้งแพ็กเกจ)
3. เปิด `http://127.0.0.1:8000` ใน Chrome/Edge
4. ลองเมนู **QR Production Flow**: เลือกสถานี 1, ใส่รหัสพนักงาน, สแกน QR หรือกรอก `JOB-DEMO-001` แล้วเริ่มงาน (กล้องจะขอสิทธิ์)
5. ลองเมนู **ตรวจวิดีโอย้อนหลัง** → เลือกวิดีโอตัวอย่าง → กด **เริ่มวิเคราะห์วิดีโอ**
6. ลองเมนู **ตรวจสอบสด** → เลือกสถานี/อนุญาตกล้อง → ให้เห็นสีและจำนวนชิ้นตามที่กำหนดต่อเนื่อง แล้วกด **หยุดและบันทึกผล**

## เปิดผ่าน Terminal

```bash
cd SOPVision-AI
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

> **สำคัญ:** Browser เปิด Webcam ได้บน `localhost` / `127.0.0.1` หรือ HTTPS (ถ้าเข้าจากมือถือผ่าน IP LAN ทั่วไป อาจถูกบล็อกกล้อง)

## หน้าพนักงานประจำสถานี

### กล้องสดและย้อนหลังตลอดช่วงเปิดกล้อง

เมื่อเปิดกล้องใน **หน้าพนักงาน**, **QR Flow**, **ตรวจสด** หรือ **หน้าสแกน QR** ระบบจะลงทะเบียนกล้องและแชร์ให้หน้า `/admin` อัตโนมัติ โดยไม่ต้องรอเริ่มชิ้นงาน มีแถบแจ้งบนหน้ากล้องว่าแอดมินดูสดและกำลังบันทึกย้อนหลังอยู่

- หน้าแอดมินส่วน **กล้องสดทั้งหมด** รับภาพผ่านการเชื่อมต่อเดียวสำหรับทุกกล้อง เป้าหมายประมาณ 4 ภาพ/วินาที แสดงสถานี หน้าที่เปิดกล้อง พนักงาน และเวลารับภาพล่าสุด ภาพที่ขาดเกิน 5 วินาทีจะแสดงออฟไลน์ ไม่แสดงภาพค้างว่าเป็น LIVE
- วิดีโอย้อนหลังบันทึกแยกจากคลิปตรวจชิ้นงาน จึงครอบคลุมช่วงรอสแกน เปลี่ยนงาน และแยกงานเสียด้วย แบ่งเป็นคลิปอิสระทุก 30 วินาที เปิดดูได้หลังคลิปนั้นส่งครบ และปิดคลิปท้ายเมื่อกดปิดกล้องตามปกติ ค้นหาตามกล้อง พนักงาน สถานี หน้าที่เปิด และช่วงเวลาเริ่มรับคลิปได้
- ไฟล์อยู่ที่ `media/cameras/` ข้อมูลอยู่ใน `camera_sessions`, `camera_segments`, `camera_chunks` การส่งวิดีโอซ้ำไม่ต่อข้อมูลซ้ำ หากรับไม่ครบจะไม่แสดงว่าคลิปสมบูรณ์ คลิปที่หลุดกลางคันจะแสดง **คลิปไม่ครบ** และอาจเปิดไม่ได้
- เมื่อเริ่มรอบงานจากหน้าพนักงานหรือ QR Flow ระบบเชื่อมช่วงเวลาของกล้องกับ QR และ `attempt_id` โดยตรง; หนึ่งกล้องต่อเนื่องเชื่อมหลายงานได้โดยแยกช่วงเวลา รายงาน Live/Upload ใส่ QR ที่มีอยู่ในระบบเพื่อรวมในประวัติเดียวกันได้ และเลือก `attempt_id` เฉพาะได้เมื่อสถานีตรงกับรอบงาน
- หน้าแอดมินมี **ค้นประวัติงานรวมด้วย QR/รหัสรอบงาน** รวมรอบงานทุกสถานี รายงาน Live/Upload และคลิปกล้องที่สัมพันธ์กับช่วงรอบงาน ส่วนค้นคลิปย้อนหลังรองรับ QR ด้วย ข้อมูลเก่าที่ไม่มีความสัมพันธ์ชัดเจนจะคงอยู่และไม่ถูกจับคู่จากเวลา/พนักงานโดยคาดเดา
- API `GET /api/traceability?qr=<QR>` หรือ `?attempt_id=<ID>` คืนข้อมูลรวมของ QR; `?key=<QR-or-ID>` รองรับช่องค้นหาเดียว รายงานตรวจสด/อัปโหลดรับ `qr` และ `attempt_id` เป็นฟิลด์ไม่บังคับ และจะปฏิเสธ QR/รอบงานที่ไม่มีอยู่หรือไม่ตรงกัน
- ต้องเปิดหน้ากล้องไว้และเชื่อมต่อเซิร์ฟเวอร์ได้ โทรศัพท์ที่ล็อกหน้าจอ ปิดแท็บ หรือถูกระบบพักแอปอาจหยุดส่งภาพและคลิปท้ายอาจหาย ไม่สามารถดูสดเมื่ออุปกรณ์หยุดส่งได้ หลังหลุดเกิน 45 วินาทีต้องเปิดกล้องใหม่
- เป็นกล้องที่เปิดผ่านเว็บแอปนี้เท่านั้น ไม่เข้าถึงแอปกล้องหรือกล้องอื่นนอกระบบ ไม่มีเสียงและไม่มีการเปิดกล้องลับ พนักงานต้องอนุญาตกล้องก่อนทุกครั้งตามการตั้งค่าของเบราว์เซอร์
- ใช้พื้นที่ดิสก์ต่อเนื่อง ไม่มีระบบลบย้อนหลังอัตโนมัติ หากพื้นที่เหลือน้อยจะหยุดรับและแจ้งข้อผิดพลาด หน้าแอดมินยังใช้ข้อจำกัดเรื่อง Login/Role ของโปรเจกต์เดิม

หลังอัปเดตให้รีเฟรชทั้งหน้ากล้องและหน้าแอดมิน กล้องที่เปิดด้วยหน้าเวอร์ชันเดิมต้องเปิดใหม่จึงเริ่มแชร์และเก็บย้อนหลังแบบต่อเนื่องได้ ไม่มีการสร้างภาพย้อนหลังให้ช่วงที่ยังไม่ได้บันทึก

การเพิ่มตารางเชื่อมกล้องกับรอบงานสำรองฐานข้อมูลเดิมเป็น `sopvision.pre-traceability-<UTC timestamp>.bak` ก่อน migration โดยไม่แก้ไขหรือลบประวัติเดิม

ทดสอบเพิ่ม: `node tests/camera_share_lifecycle.cjs` และ `python tests/smoke_camera_network.py` (อย่างหลังใช้ใบรับรอง `.certs/` และพอร์ตชั่วคราว พร้อมฐานข้อมูลแยกจากข้อมูลจริง)

### ข้อมูลการซิงก์งานผลิต

เปิด **แอดมิน / งานผลิตจริง** หรือ `/admin` เพื่ออ่านข้อมูลจาก `flow_attempts` และ `flow_audit` ในฐานข้อมูลเดียวกับหน้าพนักงาน หน้าแอดมินดึงข้อมูลทุก 2 วินาทีและแสดงเวลาซิงก์ล่าสุด หากติดต่อเซิร์ฟเวอร์ไม่ได้จะแจ้งว่าข้อมูลอาจเก่า

- เห็น QR, รหัสพนักงาน, สถานี, ขั้นตอนที่ตรวจแล้ว, ภาพกล้องล่าสุด, ขนาด/จำนวนส่วนวิดีโอที่รับ และผลปิดงาน
- กดรายละเอียดเพื่อดู SOP ที่บันทึกไว้ตอนเริ่มงาน หลักฐาน วิดีโอ และประวัติเหตุการณ์ของรายการนั้น ค้นหาด้วย QR/พนักงาน/รหัสรายการ กรองสถานีและผลได้
- “รอบงานผ่านสถานี” นับการทำงานแต่ละสถานี ส่วน “ชิ้นงานผ่านครบทุกสถานี” นับ QR ที่ผ่านทั้ง 3 สถานีจริง ไม่ใช้ยอดสองอย่างนี้ปนกัน
- เซิร์ฟเวอร์ยืนยันผลและเก็บ audit ใน transaction เดียวกัน ส่งคำขอปิดงานซ้ำจะคืนผลเดิม ไม่มีการเปลี่ยนผ่านเป็นไม่ผ่านหรือสร้างเหตุการณ์ปิดซ้ำ
- หน้าพนักงานใช้รหัสคำขอไม่ซ้ำตอนเริ่มงาน การส่งซ้ำได้รายการเดิม ส่วนวิดีโอลำดับเดิมจะรับซ้ำเฉพาะเมื่อ SHA-256 ตรงกัน จึงไม่ต่อข้อมูลซ้ำลงไฟล์ หากคำขอเริ่มงานยังไม่ยืนยัน หน้าพนักงานจะให้ตรวจสถานะก่อนเริ่มชิ้นใหม่
- `start_mobile.bat` เปิด HTTPS ผ่าน `mobile_gateway.py` ไปยัง backend เดียวกับคอมพิวเตอร์ที่ `127.0.0.1:8000` หาก backend ยังไม่เปิดจะเริ่มให้เอง ตัว gateway ไม่เปิดฐานข้อมูลและไม่รีเซ็ตงานที่กำลังทำ การเปิดสอง `main:app` แยกโปรเซสใช้ฐานข้อมูลเดียวกันไม่รองรับ

หน้าแอดมินนี้เชื่อมข้อมูลจริงในโปรเจกต์แล้ว มี Login/Role และคิวอนุมัติตรวจซ้ำ แต่ยังไม่มีการเชื่อม MES/ERP ภายนอก และการผ่านเกณฑ์ตรวจสีไม่ได้พิสูจน์คุณภาพประกอบจริง

ทดสอบ: `python -m pip install pytest httpx` แล้วรัน `python -m pytest tests -q` (รวมทดสอบส่งคำขอซ้ำพร้อมกัน ไฟล์บันทึกล้มเหลว และข้อมูลจากมือถือผ่าน gateway ถึงแอดมิน)

เปิดเมนู **หน้าพนักงานแต่ละสถานี** หรือ `/worker?station=1` (เปลี่ยนเป็น 2 หรือ 3 ได้) ระบุรหัสพนักงาน แล้วเปิดกล้อง หน้าจอแสดงภาพสด ชิ้นงานปัจจุบัน และ SOP ของสถานีนั้น

- กล้องอ่าน QR อัตโนมัติขณะไม่มีงาน รองรับเครื่องสแกน USB หรือกรอกรหัสแล้ว Enter ด้วย
- เริ่มบันทึกวิดีโอแยกต่อชิ้นทันทีหลังสแกนสำเร็จ และบันทึกต่อเนื่องตลอดงานไม่ว่าจะผ่านหรือผิดขั้นตอน แม้ตรวจครบแล้วก็ยังไม่หยุด; กล้องตรวจ QR งานถัดไปต่อเนื่อง หรือใช้เครื่องสแกน USB/กรอกรหัสระหว่างทำงานเพื่อสั่งปิดงานเดิม
- เมื่อสแกน QR งานถัดไป ระบบตรวจเฟรมล่าสุดซ้ำทุกขั้นก่อนปิดงานเดิม; ผ่านครบจึงปลดล็อกสถานีถัดไป ส่วนขั้นที่หายไป ภาพไม่นิ่ง ผิดลำดับ หรือไม่ผ่านเกณฑ์จะถูกบล็อก
- เมื่อจบงานที่ไม่ครบ/ผิดลำดับ/หยุดกลางงาน ระบบบันทึกภาพสรุปพร้อมกรอบแสดงสีที่ตรวจพบและผลรายขั้น ภาพและผลตรวจถูกเก็บเป็นหลักฐานประจำรายการ
- หากผิดลำดับ/ลำดับไม่ชัด ระบบแจ้งเตือนและยังบันทึกวิดีโอต่อจนสแกน QR ใหม่; ขั้นที่ผ่านแล้วคงประวัติไว้ แต่ไม่ลบล้างการผิดลำดับ
- สแกน QR งานใหม่ได้ทั้งผ่านกล้องหรือเครื่องสแกน/กรอกรหัสระหว่างงาน ระบบจะยืนยันผลชิ้นเดิมก่อนเริ่มชิ้นใหม่ งานที่ไม่ครบหรือผิดลำดับจะไม่ผ่านและไม่ปลดล็อกสถานีถัดไป
- งานที่ไม่ผ่านหรือหยุดกลางงานเริ่มซ้ำไม่ได้ทั้งหน้าใหม่และ API เดิม ไม่มีปุ่มแก้ผลหรือปลดล็อกสำหรับพนักงาน งาน QR อื่นเริ่มต่อได้ทันที ผลล็อกคงอยู่หลังรีสตาร์ต
- รหัส QR ต้องแยกต่อชิ้นงาน หากใช้รหัสเดียวกับทุกชิ้น ระบบจะแยกชิ้นที่ผ่านแล้วหรือถูกพักออกจากกันไม่ได้
- ใช้ปุ่มกล้องเพื่อสแกน QR ต่อเนื่องแล้วเริ่มงานเมื่ออ่านได้; QR เดิมไม่ทำให้เริ่มซ้ำ โหมดตรวจเร็วส่งภาพทุก 80 ms (สูงสุดประมาณ 12 ภาพ/วินาทีเมื่อเครื่องและเครือข่ายทัน); ให้แต่ละขั้นมองเห็นชัดก่อนทำขั้นถัดไป
- กล้องมือถือทำงานบนหน้าพนักงานที่เปิดบนมือถือโดยตรง ยังไม่ใช่การส่งภาพกล้องมือถือเข้าโปรแกรมกล้องของ Windows

### เปิด HTTPS สำหรับทดสอบกล้องมือถือใน Wi-Fi เดียวกัน

1. ดับเบิลคลิก `start_mobile.bat` หรือติดตั้ง `python -m pip install -r requirements-mobile.txt` แล้วรัน `python start_mobile.py` เซิร์ฟเวอร์จะเปิดพอร์ต **8443** และแสดง URL เช่น `https://192.168.1.20:8443/worker?station=1` (ใช้ IP ที่แสดงจริง)
2. ตัวเปิดสร้าง CA สำหรับทดสอบและใบรับรองใน `.certs/` ให้ส่งเฉพาะ **`.certs/sopvision-ca.crt`** ไปยังมือถือด้วยวิธีที่คุณใช้ส่งไฟล์ตามปกติ ห้ามส่ง `server-key.pem` โปรแกรมไม่ติดตั้งใบรับรองหรือเปลี่ยน Firewall ให้อัตโนมัติ
3. **Android:** ติดตั้งไฟล์ CA ใน Settings → Security → Encryption & credentials → Install a certificate → CA certificate (ชื่อเมนูขึ้นกับรุ่น) จากนั้นเปิด URL ใน Chrome
4. **iPhone/iPad:** เปิดไฟล์ CA → ติดตั้งโปรไฟล์ใน Settings → General → VPN & Device Management แล้วเปิด Full Trust สำหรับ “SOPVision Local Test CA” ใน General → About → Certificate Trust Settings จากนั้นเปิด URL ใน Safari
5. เปิด URL HTTPS บนมือถือ เลือกสถานี ใส่รหัสพนักงาน กด **เปิดกล้อง / เชื่อมกล้องมือถือ** และอนุญาตกล้องหลัง ทดสอบ QR ตัวอย่างจาก `media/demo/QR_JOB-DEMO-001.png` บนอีกหน้าจอ หากเบราว์เซอร์ไม่มี BarcodeDetector ระบบส่งภาพให้ OpenCV อ่าน QR สำรอง
6. หากเข้าไม่ได้ ตรวจว่า Wi-Fi เข้าถึงกันและ Windows Firewall อนุญาต Python/พอร์ต 8443 ในเครือข่ายส่วนตัว หาก IP เปลี่ยนให้รันใหม่ (`python start_mobile.py --ip IP-ที่ต้องการ` ระบุเองได้) หากใบรับรองถูกสร้างใหม่ให้ติดตั้ง CA ใหม่บนมือถือ

ใช้ CA นี้เฉพาะเครื่องทดสอบที่คุณดูแล และลบออกจากมือถือเมื่อเลิกทดสอบ ใบรับรองมีอายุ 90 วัน ระบบเดิมยังไม่มี Login/Role จึงให้ใช้ในเครือข่ายทดสอบส่วนตัวเท่านั้น หยุดเซิร์ฟเวอร์เดิมก่อนเปิดตัวใหม่เพื่อไม่ให้มีสองโปรเซสใช้ฐานข้อมูลเดียวกันขณะทำงาน

เอกสาร: [ข้อกำหนด HTTPS สำหรับ getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [Uvicorn HTTPS options](https://www.uvicorn.org/deployment/)

## ใหม่: QR Production Flow (งานหนึ่งชิ้นต้องผ่านทุกสถานีตามลำดับ)

**รองรับ QR เดิม:** ใช้ข้อความ QR ใบงานเดิมเป็นตัวระบุงานได้ ไม่จำเป็นต้องเปลี่ยนสติกเกอร์ หาก QR แต่ละจุดมีรูปแบบคนละชนิด ต้องเชื่อมต่อ MES/ERP เพื่อแปลงเป็น Job ID เดียวกันก่อนใช้งานจริง **MVP รับ QR ใดก็ได้เป็น Job ใหม่** และยังไม่เชื่อม MES/ERP หรือระบบยืนยันตัวตน

### ตัวอย่างการทำงาน

1. เลือก **Station 01**, ระบุรหัสผู้ปฏิบัติงาน (แบบข้อความสำหรับทดลอง) และสแกน `JOB-DEMO-001` ผ่านช่องรับเครื่องสแกน USB หรือปุ่มสแกนด้วยกล้อง (ถ้า Browser รองรับ `BarcodeDetector`) หรือกรอกด้วยมือ
2. หลังตรวจสิทธิ์กับเซิร์ฟเวอร์ กล้องจะเริ่มส่งภาพให้ OpenCV ตรวจสีและลำดับอัตโนมัติ การบันทึกวิดีโอเป็นข้อมูลเสริม ไม่ใช่เงื่อนไขเริ่มหรือผ่านงาน
3. Station 01 มีสองขั้นตอน: **เขียว → แดง**; ระบบนับสีที่เห็นจากทั้งภาพและยืนยันลำดับ/จำนวนด้วยภาพสองเฟรม การพบสีแดงก่อนฐานจะถูกบันทึก `blocked`
4. เมื่อสีและจำนวนชิ้นส่วนครบตามลำดับ ระบบตรวจภาพสุดท้ายและปิดงานให้อัตโนมัติ สถานี 2 จะเปลี่ยนจาก `locked` เป็น `ready` ทันที (ไม่ใช้สถานะจาก Frontend มาตัดสิน)
5. Station 02 ทำ **น้ำเงิน → เหลือง**, Station 03 ทำ **ส้ม → ม่วง** โดยใช้ QR เดิมทุกสถานี
   > หมายเหตุ: ชุดขั้นตอน QR Flow เป็นค่า Demo ใน `production.py` แยกจาก SOP Management
6. ถ้าสีไม่ครบ ผิดลำดับ หรือหยุดงานก่อนชิ้นส่วนครบ QR ชิ้นนี้จะถูกแยกพักและ **ถูกปฏิเสธโดย Backend (HTTP 409)** ทุกสถานี พนักงานแก้ไขหรือเริ่มชิ้นเดิมซ้ำไม่ได้ ให้นำงานออกแล้วสแกนชิ้นถัดไป ปัญหาการบันทึกวิดีโอไม่เปลี่ยนผลตรวจสีและจำนวน
7. โหมด **ตรวจสอบสด** และ **ตรวจวิดีโอย้อนหลัง** แบบเดิมยังอยู่ และทำงานแยกจากการปลดล็อกสถานี เพื่อไม่ให้การตรวจย้อนหลังเปลี่ยนสถานะการผลิตโดยไม่ได้รับอนุญาต

**สแกน QR ตัวอย่าง:** ดูภาพ `media/demo/QR_JOB-DEMO-001.png` หรือพิมพ์ `JOB-DEMO-001` ทดสอบได้เลย

**วิดีโออยู่ที่** `media/recordings/` (ชื่อไฟล์อ้างอิง Attempt ID แบบสุ่ม ไม่ใช้ข้อมูล QR ตั้งชื่อไฟล์) ผลตรวจและสถานะสถานีเก็บในฐานข้อมูล `sopvision.db`; หากรีสตาร์ตเซิร์ฟเวอร์ระหว่างทำงาน จะทำเครื่องหมายเซสชันที่ค้างเป็น `interrupted` และไม่ปลดล็อกงาน

**ข้อจำกัดสำคัญสำหรับโรงงานจริง:**
- ฟีเจอร์นี้ล็อกเฉพาะการ **เริ่มงานใน SOPVision Web App** ไม่มีการต่อกับ PLC/MES และ **ไม่สามารถหยุดเครื่องจักรหรือขัดขวางงานทางกายภาพได้**
- ยังไม่ได้ใช้ Model ตรวจท่าทางการขัน/การหยิบจริง ตัวตรวจหลักคือ **สี + ลำดับ** ซึ่งอาจพลาดจากแสงหรือมุมกล้อง และไม่ควรใช้ตัดสินคุณภาพงานจริงโดยลำพัง
- เวอร์ชันนี้ **ยังไม่มี Login/Role/การรับรอง QR ต้นทาง**: ไม่เหมาะนำไปเชื่อมเครื่องจักรใช้งานจริง การผูก QR กับ Job ID จากระบบโรงงาน, ผู้ตรวจสอบมนุษย์พร้อม audit สำหรับการแก้ไข/อนุมัติข้อผิดพลาด, นโยบายเข้าถึงและลบวิดีโอ, ความปลอดภัยข้อมูล, และกลไก fail-safe ก่อน
- กล้องต้องใช้งานได้ผ่าน `localhost` หรือ HTTPS; การบันทึกวิดีโอใช้ `MediaRecorder` เมื่อเบราว์เซอร์รองรับ แต่ไม่จำเป็นต่อการผ่านสีและจำนวน หน้าพนักงานมี OpenCV QR decoder ฝั่งเซิร์ฟเวอร์สำรองเมื่อเบราว์เซอร์ไม่มี `BarcodeDetector` ส่วนหน้า QR Flow ใช้ native detector หรือเครื่องอ่าน USB / กรอกข้อความ

## ตรวจสอบกับชิ้นงานจริงแบบจำลอง

- ตั้งกล้องนิ่งเหนือโต๊ะ ฉากหลังสีเรียบ แสงสม่ำเสมอ ไม่มีกระดาษหลากสีบนโต๊ะ
- วาง **แผ่นฐานสีเขียว** ก่อน → **ชิ้นส่วนสีแดง** → **สีน้ำเงิน** → **สีเหลือง**
- ให้การ์ด/ชิ้นส่วนแต่ละสีมีพื้นที่ไม่น้อยกว่า ~0.5–1.0% ของกรอบกลางภาพ (เปลี่ยนเกณฑ์ในหน้าจัดการ SOP ได้)
- เมื่อพบสีอย่างน้อย 2 ครั้งใน 3 เฟรม ภายใน 0.4 วินาที ระบบยืนยันการพบสี โดยยอมให้มือบังระหว่างกลางได้ 1 เฟรม ขั้นตอนที่ยืนยันแล้วคงผลแม้ถูกบังภายหลัง แต่จะไม่เดาขั้นตอนที่ไม่เคยเห็นหรือสีที่ปรากฏพร้อมกัน
- หากเพิ่งพบหลายสีในเฟรมเดียวกัน จะไม่สามารถยืนยันลำดับที่เกิดขึ้นระหว่างเฟรมได้ ต้องตรวจสอบด้วยคน
- เมื่อพบขั้นตอนหลัง ก่อนขั้นตอนหน้า จะขึ้น **ผิดลำดับ** และไม่ถูกปรับเป็นผ่านในภายหลัง

## Gemini AI Review (ตัวเลือก)

ทำงานได้โดยไม่ต้องมี Gemini key หากต้องการให้ AI สรุปและตรวจจุดไม่แน่นอนของภาพหลังจบงาน ให้ตั้ง Environment variable บนคอมที่รัน Python ก่อนเริ่ม server

ติดตั้งส่วนเสริม `python -m pip install -r requirements-ai.txt` ก่อน แล้วตั้งค่าคีย์ใน PowerShell:
```powershell
$env:GEMINI_API_KEY="YOUR_KEY_HERE"
$env:GEMINI_MODEL="gemini-flash-latest"
python -m uvicorn main:app --reload
```

เปิดรายงานตรวจสด/อัปโหลดแล้วกด **ให้ Gemini วิเคราะห์ภาพหลักฐาน** หรือเปิดรายการ QR ในหน้าแอดมินแล้วกด **ให้ Gemini วิเคราะห์รายการนี้** เซิร์ฟเวอร์จะส่งภาพหลักฐานและผลตรวจขั้นตอน (ไม่ส่ง QR/รหัสพนักงาน) ไปยัง Gemini API (อาจมีค่าใช้จ่ายและข้อกำหนดการเก็บข้อมูล) โดย **ไม่ส่งคีย์ไปยัง Browser** ชื่อโมเดลสามารถปรับได้หากรุ่นที่ระบุไม่พร้อมใช้งานในบัญชีของคุณ ผลเป็น second opinion เท่านั้น ไม่แก้ผลผ่าน/ไม่ผ่านและไม่เปลี่ยนการปลดล็อกสถานี

## API สำคัญ

- `GET /api/flow/stations` — SOP ประจำสถานีในตัวอย่าง
- `POST /api/flow/lookup` — ดูสถานะของ QR และสถานีที่พร้อม/ล็อก
- `POST /api/flow/start` — เช็กสิทธิ์และเริ่มตรวจสถานี (เซิร์ฟเวอร์บังคับลำดับ)
- `POST /api/flow/frame/{id}` — ส่งภาพเพื่อตรวจสด
- `POST /api/flow/recording/{id}/{sequence}` — ส่ง Video Chunk ที่บันทึกจริง
- `POST /api/flow/finish/{id}` — บันทึกผลผ่าน/บล็อกและปลดล็อกขั้นต่อไปเฉพาะเมื่อผ่าน
- `POST /api/flow/abort/{id}` — ยุติแบบไม่ปลดล็อก
- `GET /api/flow/attempts/{id}` — รายละเอียดการทำงานและหลักฐาน
- `POST /api/flow/attempts/{id}/ai-review` — Gemini วิเคราะห์ภาพหลักฐาน QR เพิ่มเติม (optional; second opinion เท่านั้น)
- `GET /api/steps` — อ่าน SOP
- `PUT /api/steps` — บันทึก SOP
- `POST /api/live/start` — เปิด session ตรวจสด
- `POST /api/live/frame/{id}` — ส่งภาพ JPEG ตรวจสด
- `POST /api/live/stop/{id}` — บันทึกรายงาน
- `POST /api/upload` — อัปโหลดวิดีโอ + วิเคราะห์ย้อนหลัง
- `GET /api/reports` — ประวัติการตรวจ
- `GET /api/reports/{id}` — รายละเอียดรายงาน
- `POST /api/reports/{id}/ai-review` — Gemini ตรวจภาพเพิ่มเติม (optional)

API Docs: `http://127.0.0.1:8000/docs`

## จุดที่ควรพัฒนาในโปรเจกต์จบจริง

1. สร้างชุดข้อมูลวิดีโอจริงหลายมุมกล้องและสภาพแสงพร้อม Ground Truth
2. ฝึก object detector / action recognition model ให้จำแนกชิ้นส่วนจริงและท่าทางได้
3. แยกสีที่มองเห็นออกจากหลักฐาน **การทำขั้นตอนเสร็จจริง** (presence ≠ action)
4. ตรวจสอบขั้นตอนผิดลำดับเทียบกับ Ground Truth และวัด Precision/Recall/F1
5. เพิ่มบัญชีผู้ใช้จริงและ Supervisor Review, ลบ/จำกัดอายุไฟล์, สิทธิ์ข้อมูล, ตั้งค่าขั้นตอนแยกแต่ละรุ่นงาน, นโยบายกล้อง และการเชื่อม MES/ERP โดยไม่กระทบความปลอดภัยเครื่องจักร

**Privacy:** ใช้ข้อมูลที่ได้รับอนุญาตเท่านั้น และต้องขอความยินยอมก่อนบันทึกพนักงานจริง Prototype ไม่ทำ face recognition หรือ worker scoring

## ตรวจเร็วและการบังภาพ

กล้องสด / QR / หน้าพนักงานตั้งเป้าส่งภาพ 10 ภาพต่อวินาที และไม่ส่งคำขอเฟรมซ้อนกัน ความเร็วจริงขึ้นกับกล้อง เครือข่ายและเซิร์ฟเวอร์ วิดีโออัปโหลดตรวจสูงสุด 12 ภาพต่อวินาที การยืนยันใช้หลักฐาน 2 ใน 3 เฟรม ภายใน 0.4 วินาที และใช้เวลาที่เริ่มเห็นสีเป็นลำดับ ไม่ใช้เวลาที่เพิ่งยืนยัน จึงไม่สลับลำดับเพียงเพราะภาพหนึ่งถูกบัง

หลังยืนยันแล้ว ถ้าไม่เห็นสีเกิน 0.25 วินาที หน้าจอจะแสดงว่าหายจากภาพและจำผลเดิมไว้ นี่เป็นการจำหลักฐาน ไม่ใช่โมเดลรู้จำมือ และไม่ใช่การยืนยันว่าชิ้นส่วนยังติดตั้งอยู่ หากมือบังตั้งแต่เริ่ม ไม่เคยเห็นชิ้นส่วน หรือเห็นหลายขั้นพร้อมกัน ระบบยังต้องตรวจสอบเพิ่มเติม การล็อกงานผิดลำดับยังมีผลเหมือนเดิม ต้องทดสอบกับกล้องมือถือจริงก่อนกล่าวอ้างความเร็วหรือความแม่นยำ


## รายงานแอดมินและข้อมูลตรงกันทุกหน้า
- หน้าแรกนับงานผลิต QR จาก read model เดียวกับ /api/flow/admin ส่วนประวัติรวม /api/records แยกประเภทงานผลิตกับ Live/Upload อิสระชัดเจน ไม่ถือว่ารายงานอัปโหลดปลดล็อกงานผลิต
- หน้าพนักงานอ่านประวัติจริงจากฐานข้อมูล กรองรหัสพนักงานแบบตรงตัวและสถานี แสดง 15 รอบล่าสุด ยอดรวมเป็นทั้งหมดที่ตรงกับพนักงาน/สถานีนั้น และไม่หายเมื่อรีเฟรช
- หน้าแอดมินกรองคำค้น สถานี สถานะ และช่วงเวลาไทย ยอดการ์ดตามตัวกรอง พร้อมส่งออก CSV UTF-8 BOM สำหรับ Excel และ HTML สำหรับพิมพ์เป็น PDF แบบ A4 แนวนอน
- ส่งออกทุกหน้าที่ตรงกับตัวกรอง ไม่จำกัดเฉพาะ 50 แถวที่เปิดอยู่ รายงานเกิน 50,000 แถวจะปฏิเสธอย่างชัดเจนให้จำกัดช่วงเวลา ไม่ตัดข้อมูลทิ้งเงียบ ๆ
- CSV ป้องกัน formula injection; HTML escape ข้อมูลที่ผู้ใช้กรอก รวมเวลา +07:00 และเวลาสร้างรายงาน สถานะขั้นตอนเป็นผลที่บันทึกไว้ ไม่ประเมินใหม่ด้วย SOP ปัจจุบัน
- ตัวเลขอาจเปลี่ยนระหว่างการเปิดหน้าและกดส่งออกหากมีงานใหม่เข้ามา ให้เทียบตัวกรองและเวลาสร้างข้อมูล แต่ละ response อ่าน SQLite ภายใน transaction เดียว
- การส่งออกรายงานใช้สิทธิ์เข้าถึงหน้าแอดมินเดิม ระบบต้นแบบยังไม่มี authentication หรือ role-based access control

### ทางเข้าคอมและมือถือหลังอัปเดตรายงาน
Backend หลักทำงานบน http://127.0.0.1:8000 และหน้าแอดมินคือ /admin ส่วนพอร์ต 8001 ใช้ run_desktop_gateway.py ส่งต่อไปยัง backend หลักเดียวกัน เช่นเดียวกับ HTTPS มือถือพอร์ต 8443 ไม่ควรเปิด main:app หลาย process คนละพอร์ต เพราะเซสชันตรวจและกล้องอยู่ในหน่วยความจำของแต่ละ process

ตรวจระบบได้ด้วยชุด tests/test_reporting.py และ node tests/reporting_ui.cjs (ใช้ Playwright ใน .test-node) ส่วน tests/verify_reporting_live.py ตรวจทางเข้าคอมทั้งสองพอร์ตและ HTTPS มือถือด้วย CA ของโปรเจกต์ โดยไม่สร้างงานผลิตเพิ่ม


## บัญชีผู้ใช้ โหมดทดสอบ และการตรวจซ้ำ
- ครั้งแรกเปิดเซิร์ฟเวอร์ แล้วดับเบิลคลิก setup_admin.bat บนคอมเครื่องนี้ จะเปิดแบบฟอร์มสร้างแอดมินพร้อมรหัสตั้งค่าครั้งเดียว ให้เจ้าของระบบตั้งชื่อและรหัสผ่านเอง (อย่างน้อย 10 ตัวอักษร) ไม่มีรหัสผ่านเริ่มต้น รหัสตั้งค่าถูกลบหลังสร้างสำเร็จ
- แอดมินสร้าง/เปิด/ปิดบัญชีได้ที่ /access; ปิดบัญชีตนเองหรือแอดมินคนสุดท้ายไม่ได้ การปิดบัญชีเพิกถอน session ทันที
- พนักงานตรวจและดูประวัติงานของบัญชีตนเอง ระบบใช้ชื่อบัญชีเป็นรหัสผู้ปฏิบัติงาน; QC ดูรายงาน หลักฐาน และยืนยันแยกพัก; หัวหน้างานเพิ่มสิทธิ์อนุมัติให้ตรวจซ้ำ; แอดมินเพิ่มสิทธิ์จัดการบัญชีและ SOP
- Session 8 ชั่วโมง ใช้ cookie HttpOnly/SameSite Strict และ Secure เมื่อผ่าน HTTPS; คำขอแก้ไขต้องมี CSRF token; รหัสผ่านเก็บเป็น PBKDF2 hash และจำกัดการลองเข้าสู่ระบบผิด
- เลือกโหมดทดสอบที่หน้าตรวจงาน สร้างรอบใหม่เพื่อใช้ QR เดิมเริ่มที่สถานี 1 ได้อีกครั้ง ทุกสถานีต้องเลือกรอบเดียวกัน ขณะมีงานหรือคำขอค้างจะเปลี่ยนรอบไม่ได้
- ยอดหน้าแรกและรายงานเริ่มต้นนับผลิตจริงเท่านั้น หน้าแอดมินเลือกผลิตจริง/ทดสอบ/ทั้งหมดได้ ตัวกรองเดียวกันใช้กับ CSV และรายงานพิมพ์ รวมรหัส QR ที่อ่านได้ รหัสภายใน รอบทดสอบ และข้อมูลพิจารณาตรวจซ้ำ
- งานแยกพัก/หยุดกลางงานที่ปิดแล้วเข้าคิว /access; หัวหน้า/แอดมินอนุมัติตรวจซ้ำพร้อมเหตุผลอย่างน้อย 10 ตัวอักษร ผลเดิมไม่ถูกแก้เป็นผ่าน รอบใหม่เชื่อม rework_of กับรอบเดิม และต้องตรวจ SOP ใหม่ครบก่อนส่งต่อ
- หากไม่ได้รับภาพตรวจเกิน 45 วินาที เซิร์ฟเวอร์แยกพักงาน บันทึก connection_timeout เก็บหลักฐาน และส่งเข้าคิว การอัปโหลดวิดีโอเพียงอย่างเดียวไม่นับว่าได้รับภาพตรวจ
- ปุ่มออกจากระบบอยู่บนแถบผู้ใช้ทุกหน้า การเปิดหน้ากล้องบน iPhone ต้องเข้าสู่ระบบผ่าน HTTPS และอนุญาตกล้องบน Safari
- ตรวจอัตโนมัติด้วย tests รวมสิทธิ์/CSRF, การเพิกถอน session, test rounds, supervisor review, watchdog และ browser UI ผ่าน Edge ด้วยกล้องจำลอง การทดสอบนี้ไม่แทนการวัดความแม่นยำกับชิ้นงานจริง/มือบัง/ความเร็วจริง


## หน้าพนักงานไม่ต้องล็อกอิน
- เปิด /worker หรือ /worker?station=2 ได้โดยตรง เลือกสถานีแล้วเปิดกล้องสแกนงาน ไม่ต้องมีบัญชีหรือกรอกรหัสพนักงาน
- ระบบสร้างเซสชันสถานีให้อัตโนมัติแยกแต่ละเบราว์เซอร์ ใช้ CSRF และจำกัดการอ่าน/แก้ไขเฉพาะงานและกล้องของเซสชันนั้น ไม่ได้เปิด API แอดมินให้สาธารณะ
- ช่องประวัติแสดงงานของเซสชันนี้ในสถานีที่เลือก พนักงานคนอื่นในคนละเครื่องเริ่มทำสถานีถัดไปได้เมื่อ QR ผ่าน SOP จากสถานีก่อนหน้าแล้ว
- บันทึกผู้ปฏิบัติงานเป็นรหัสเซสชันสถานีอัตโนมัติ ไม่อ้างว่าเป็นตัวตนพนักงานจริง แอดมินยังดูรวมทุกสถานีและส่งออกรายงานได้
- หน้า /admin, /access, รายงาน, การแก้ SOP และการอนุมัติตรวจซ้ำยังต้องเข้าสู่ระบบและมีสิทธิ์เหมือนเดิม
